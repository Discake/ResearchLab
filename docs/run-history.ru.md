# M3: чтение истории Run

`RunHistory` использует существующие `IResearchStore` и SQLite-адаптер. Чтение не запускает
задачи, не восстанавливает устаревшие Run, не меняет статус/версию и не сохраняет агрегаты.

```csharp
var history = new RunHistory(store);
var details = await history.GetRunAsync(runId, cancellationToken);
var page = await history.ListRunsAsync(experimentId,
    new RunPageRequest(offset: 0, pageSize: 25), cancellationToken);
// Существующий сервис логов с тем же настроенным приватным корнем:
var logs = new RunLogs(store, logFiles);
var paths = await logs.GetPathsAsync(details.Id, cancellationToken);
// paths равен null при отсутствии каталога; пути относительны корня логов.
```

Детали и элементы списка содержат ID, Experiment ID, статус, даты создания/старта/окончания,
скопированные типизированные параметры только для чтения, exit code и безопасную диагностику.
Изменяемый Run, пути workspace/executable, снимок окружения и произвольный FailureReason
не возвращаются. Диагностика формируется из статуса, факта старта и exit code, а не очисткой
текста исключения; сохранённая диагностика не меняется. Параметры остаются записанными
входными данными пользователя: это не механизм удаления секретов. Логи могут содержать
приватный вывод процесса; для локального чтения используется существующий
`RunLogs.OpenReadAsync(RunId, RunLogStream, token)`. Новый ввод путей или reader не добавлен.

Неизвестный Run даёт `CatalogException` с кодом `RunNotFound`, неизвестный Experiment —
`ExperimentNotFound`. Для существующего Experiment без запусков возвращается пустой список.
Существующий nullable-контракт GetRunAsync в store не изменён.

Размер страницы по умолчанию — 50, допустимо 1–100 элементов и целочисленный offset >= 0.
Недопустимые значения дают `ArgumentOutOfRangeException` до обращения к SQLite. Порядок:
CreatedAtUtc по убыванию, затем ID по возрастанию в TEXT-порядке SQLite. Domain нормализует
даты Run в UTC; существующий TEXT-формат SQLite сохраняет хронологический порядок, включая
доли секунды. Параметризованный SQL выполняет фильтрацию Experiment, сортировку, LIMIT и
OFFSET до материализации. Вся история не загружается, метрики не присоединяются, общий
COUNT не выполняется. Миграция схемы и универсальный query framework не нужны.

Пустая/неполная страница означает текущий конец истории. Отдельные запросы не образуют
общий снимок: параллельные вставки могут сдвинуть offset и вызвать повтор/пропуск элементов.
Стабильный межзапросный snapshot или cursor не обещаются. Токены отмены передаются SQLite.

Интеграционные тесты используют синтетические данные SQLite: пустая/неизвестная история,
изоляция Experiment, одинаковые даты и порядок ID, доли секунды, повторные страницы,
лимиты/defaults, все статусы, сохранность версий/доказательств, неизменяемые копии параметров
и существующие логи.
