# M3.6 — local Run workflow

## Explicit recovery

```text
researchlab --database <existing-sqlite-file> --data-dir <private-storage-root> run recover
```

The CLI calls `RunRecovery.RecoverAsync`, without initialization or migrations. JSON stdout
contains `recovered` Run IDs, `conflicts` Run IDs (still nonterminal after a competing write),
and `unverifiedSessions` session IDs. The last list includes active owners and unavailable,
unsafe or concurrently claimed ownership evidence; it does not label them dead.
Exit 0 means the scan completed, including when some entries were skipped. Inspect all lists;
retry conflicts explicitly. Storage failure returns 4, cancellation returns 130.

Only Created/Running Runs with verified ended ownership become Interrupted. Repeated calls
leave terminal Runs unchanged. Recovery never uses saved PIDs to kill processes and never
changes active/unverified owners. The warning on stderr is unconditional: Interrupted does
not prove child-process termination. See [ownership details](run-recovery.md).

## Program filesystem contract

Before OS startup, ProcessRunner allocates `<data-dir>/<RunId:N>/output`, beside `stdout.log`
and `stderr.log`. Run IDs are generated by Application; configuration, arguments and stdout
cannot select this path. The absolute path replaces any inherited `RESEARCHLAB_OUTPUT_DIR`.
The program must explicitly write results there. CWD remains the validated project workspace,
preserving relative input/resource paths; ordinary relative writes still target that workspace.
`RESEARCHLAB_PARAMETERS_JSON` is unchanged.

The configured storage root must remain stable when reopening a database. Paths derive from
Run ID without new database fields or migrations. Distinct concurrent Runs have distinct
directories. Existing attempt directories are refused, log reservation uses CreateNew, and
existing output directories are refused; partial allocations remain and are never retried in
place. Allocation failure prevents OS startup and records Failed without invented PID/exit code.
Runs rejected before execution or canceled before startup may have no output directory.
Older Runs are not backfilled. Results remain available locally after success or failure.

Creation rejects symlinks, junctions and reparse points in the output path and all existing
ancestors. Keep storage private and outside the workspace. This is not file isolation: trusted
programs can ignore the variable, modify other accessible files or replace paths after checks.
Concurrent hostile filesystem replacement remains a TOCTOU limitation. Output files have no
quota, checksum, immutability, registration, download API or publication semantics yet. M4
protocol and artifact registration remain unimplemented; the log byte cap does not limit files.

## Remaining M3 boundaries

The local CLI scenario now covers initialization, import, Experiment creation, reviewed start,
bounded logs, terminal history, managed Ctrl+C, explicit recovery and per-Run output allocation.
M3.7c now adds [Windows Job group ownership](windows-group-lifecycle.md), including
descendants surviving root exit. Cleanup denial retains the foreground owner for retry.
The complete CLI crash-window matrix remains M3.7d; Unix behavior retains its weaker,
unverified guarantees. Live log UI belongs to M5.
