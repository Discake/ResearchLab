# Консольный host: чтение метаданных

ResearchLab.Cli связывает готовые ProjectCatalog, RunHistory и RunLogs. В CLI находятся
разбор аргументов, форматирование ответа и коды завершения. Эти команды чтения не добавляют
доменных правил, сеансов владельца, recovery или исполнения задач. Тот же CLI теперь
поддерживает явную подготовку БД/проекта/эксперимента и foreground-запуск:
[воспроизводимое руководство](foreground-run.ru.md).

Имя исполняемого файла — `researchlab`. Из собранного checkout он запускается через
`dotnet run --no-build --project src/ResearchLab.Cli -- <аргументы>` или
`dotnet src/ResearchLab.Cli/bin/Debug/net10.0/researchlab.dll <аргументы>`.
Это локальная программа, не установленный глобальный tool.

Для каждого чтения обязательны `--database <sqlite-file>` и `--data-dir <log-root>`.
Опции разрешены до и после команды. Пути с пробелами заключаются в кавычки. Относительные
пути разрешаются от текущего каталога вызывающего процесса, не от каталога БД.
Неявных расположений БД и defaults из переменных окружения нет. Директория данных —
именно приватный корень, ранее переданный RunLogFiles: не workspace, не общее хранилище
артефактов M4 и не каталог с автоматически добавленной подпапкой `logs`.
Отсутствующий корень логов допустим и не создаётся; `run show` вернёт `logs: null`.
Существующий файл вместо директории данных отклоняется.

Поддерживаемые команды:

```text
project list
experiment list --project <project-id>
run list --experiment <experiment-id> [--offset <n>] [--page-size <n>]
run show <run-id> [--include-logs]
--help
```

Фильтры обязательны, ID — непустые GUID. Страницы Run используют RunPageRequest и
RunHistory: defaults 0/50, размер 1–100, CreatedAtUtc по убыванию и ID по возрастанию.
CLI не повторяет сортировку/пагинацию и не загружает автоматически все страницы истории.
Ограничения offset при параллельных вставках описаны в [чтении истории](run-history.ru.md).

При успехе stdout содержит одно JSON-значение с отступами: массив для списка (включая
`[]`), объект для show. У проектов не выводится путь workspace. Для Run используются
безопасная диагностика Application, записанные параметры, даты и exit code; show также
возвращает известные относительные пути stdout/stderr через RunLogs. Опция `--include-logs`
также возвращает ограниченный, JSON-экранированный текст логов согласно foreground-руководству.
JSON экранирует управляющие символы сохранённых строк, не позволяя им стать командами
терминала. Параметры могут содержать приватный пользовательский ввод: это локальный
просмотр, а не публичный экспорт.

SQLite открывается с Mode=ReadOnly. Отсутствующая, пустая, повреждённая или несовместимая
БД даёт ошибку: команды чтения не создают БД и не применяют миграции. При чтении файлы
не удаляются и задачи не запускаются. Поиск логов сохраняет существующие проверки границ/ссылок и TOCTOU-ограничения
приватного доверенного корня. Нужные существующие БД и корень логов выбираются явно.

Ошибки идут в stderr без dump исключения, исходной диагностики БД и приватных путей:

| Код | Значение |
| --- | --- |
| 0 | Успех, включая пустой список и отдельный --help/-h |
| 1 | Непредвиденная ошибка чтения |
| 2 | Неверная/неполная команда, опции, GUID, пагинация или отсутствие конфигурации |
| 3 | Project, Experiment или Run не найден |
| 4 | Ошибка файловой системы/доступа, SQLite, сохранённых данных или небезопасный путь логов |
| 130 | Чтение отменено, включая Ctrl+C |

Тесты используют синтетические временные БД: разбор/ошибки команд и чтение Application,
сохранность байтов БД и состояния сеансов, запрет записи через read-only store. Все четыре
команды также выполняются дочерними процессами через настоящий console entry point.
Измерения benchmark и исследовательские доказательства продукта тесты не создают.
