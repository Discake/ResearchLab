# M3.6 — сценарий локального Run

## Явное восстановление

```text
researchlab --database <existing-sqlite-file> --data-dir <private-storage-root> run recover
```

CLI вызывает `RunRecovery.RecoverAsync` без инициализации и миграций. JSON stdout содержит
`recovered` — ID восстановленных Run, `conflicts` — ID оставшихся нетерминальными Run после
конкурирующей записи, `unverifiedSessions` — ID сеансов с неподтверждённым состоянием.
Последний список включает активных владельцев, недоступные/небезопасные свидетельства
и сеансы, уже захваченные другим recovery; они не объявляются завершёнными.
Код 0 означает завершение проверки, даже при пропусках. Проверяйте все списки; конфликты
повторяйте явно. Ошибка хранилища даёт 4, отмена — 130.

Только Created/Running с подтверждённо завершённым владельцем переходят в Interrupted.
Повторный вызов не меняет терминальные Run. Recovery не завершает процессы по сохранённым
PID и не меняет активных/неподтверждённых владельцев. Предупреждение в stderr выводится
всегда: Interrupted не доказывает остановку дочернего процесса. Подробности —
[в контракте владения](run-recovery.ru.md).

## Контракт файловой системы программы

Перед стартом ОС ProcessRunner создаёт `<data-dir>/<RunId:N>/output` рядом с `stdout.log`
и `stderr.log`. Run ID выдаёт Application; конфигурация, аргументы и stdout не выбирают путь.
Абсолютный путь заменяет унаследованное значение `RESEARCHLAB_OUTPUT_DIR`. Программа должна
явно записывать туда результаты. CWD остаётся проверенным workspace проекта для совместимости
относительных путей ресурсов; обычные относительные записи по-прежнему идут в workspace.
`RESEARCHLAB_PARAMETERS_JSON` не меняется.

При повторном открытии БД необходимо сохранять тот же корень хранилища. Путь выводится из
Run ID без новых полей БД и миграций. Конкурентные Run получают разные каталоги. Существующий
каталог попытки отклоняется, резервирование логов использует CreateNew, существующий output
также отклоняется. Частичные результаты выделения сохраняются без повтора на месте.
Ошибка выделения предотвращает старт ОС и сохраняет Failed без выдуманных PID/exit code.
Отклонённые до исполнения и отменённые до старта Run могут не иметь каталога.
Для старых Run каталоги не создаются задним числом. Файлы остаются после успеха и ошибки.

Создание отклоняет symlink/junction/reparse point в выходном пути и существующих предках.
Хранилище должно быть приватным и находиться вне workspace. Это не изоляция файлов:
доверенная программа может игнорировать переменную, изменять другие доступные файлы или
подменить пути после проверки. Враждебная конкурентная подмена остаётся TOCTOU-ограничением.
Для выходных файлов пока нет квот, checksum, неизменяемости, регистрации, API скачивания
или публикации. Протокол и регистрация артефактов M4 не реализованы; лимит логов не ограничивает файлы.

## Оставшиеся границы M3

Локальный CLI теперь покрывает инициализацию, импорт, создание Experiment, подтверждённый
запуск, ограниченные логи, историю, управляемый Ctrl+C, явное recovery и каталог каждого Run.
M3.7c добавляет [владение Windows Job-группой](windows-group-lifecycle.ru.md), включая
потомков завершившегося корня. Отказ очистки сохраняет foreground-владельца для повтора.
Полная матрица crash windows CLI остаётся M3.7d; Unix сохраняет более слабые, непроверенные
гарантии. UI потоковых логов относится к M5.
