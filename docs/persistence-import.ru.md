# M2 — хранение и импорт проектов

Application содержит `ProjectCatalog`, `IResearchStore` и `IWorkspaceInspector`.
Infrastructure реализует проверку файлов/Git и `SqliteResearchStore`; Domain не зависит
от EF, файловой системы и процессов. Исполнитель задач, HTTP-host, UI и публикация в M2
не добавлены. Пример вызовов C# и JSON приведён в [английской версии](persistence-import.md).

## Использование API

Будущий composition root ссылается на Infrastructure. Создайте `SqliteResearchStore`
с явным путём БД и вызовите `InitializeAsync`: миграции можно применять повторно.
Родительский каталог БД должен существовать. Затем создайте `ProjectCatalog` со store
и `WorkspaceInspector`. Доступны импорт, создание Experiment, списки и повторное открытие.
Новый экземпляр store/catalog с тем же путём читает сохранённые данные.

Храните локальную БД вне импортируемых workspace, чтобы не менять их Git dirty state.
Отдельный каталог `.researchlab/` исключён из Git этого репозитория. Пути и Git-ссылки
остаются локальными метаданными, не разрешёнными автоматически для публикации.
Импорт не создаёт БД по неявному пути: выбранное хранилище инициализирует вызывающий код.

## Схема конфигурации v1

В workspace нужен UTF-8 файл `researchlab.json`: `schemaVersion: 1`, непустой объект
`tasks`, а для каждой задачи — `executable`, массив строк `args` и `timeoutSeconds`.
Все поля обязательны. Неизвестные/повторные свойства и имена задач, неподдерживаемые
версии и неверные типы отклоняются. Аргументы остаются буквальными строками: оболочки,
подстановки переменных окружения и выполнения вложенных команд нет.

Лимиты: файл 1 МиБ; 1–64 задачи; непустое имя до 128 символов; до 128 аргументов;
путь executable и каждый аргумент до 4096 символов без NUL; целый тайм-аут 1–86400 секунд.
Executable — существующий файл по относительному пути внутри workspace (на Windows,
например, `./build/benchmark.exe`). Поиска в PATH и абсолютных путей в M2 нет.
Перед импортом соберите исполняемый файл. Проверка возможности его запуска относится к M3.

Путь workspace канонизируется с разрешением ссылок. Конфигурация и executable проверяются
на принадлежность workspace до и после разрешения цепочки ссылок. Выход наружу запрещён.
Повторный импорт канонического пути отклоняется; на Windows ключ пути регистронезависимый.
Это локальная однопользовательская граница, а не ОС-песочница против процесса, параллельно
подменяющего файлы.

## Явное доверие

Импорт и создание Experiment не разрешают выполнение. Вызывающая сторона получает
`ReviewTaskAsync`, показывает владельцу executable, аргументы и тайм-аут и только после
согласия вызывает `ConfirmTaskAsync` с fingerprint просмотренной версии.
`GetTrustedTaskAsync` заново проверяет fingerprint либо возвращает ошибку.
Ни один из этих методов не запускает задачу.

Fingerprint включает ID проекта, канонические пути workspace/executable, полные байты
конфигурации и SHA-256 выбранного executable. Изменение конфигурации или файла делает
старое подтверждение недействительным. Проверка executable ограничена 256 МиБ.
Согласие хранится только в текущем экземпляре каталога; после перезапуска требуется новое.
Оно не удостоверяет транзитивно загружаемые скрипты, библиотеки и данные. Будущий runner
должен повторно проверять доверие непосредственно перед запуском; просмотр не устраняет
гонку между проверкой пути и использованием файла.

## Хранение и инварианты

Начальная миграция создаёт Projects, Experiments, Runs, MetricPoints, внешние ключи,
уникальные канонические пути и `(RunId, Sequence)`. Сложные неизменяемые определения и
снимки хранятся в JSON-столбцах, метрики — отдельными строками. DateTimeOffset сохраняет
смещение, доменная модель выдаёт UTC. `EnsureCreated` не используется.

EF восстанавливает агрегаты через закрытые конструкторы и поля, настроенные исключительно
в Infrastructure. Публичные конструкторы сохраняют проверки. Метрики Run доступны через
обёртку только для чтения. БД — доверенное состояние приложения; ручное редактирование
файла обходит прикладную границу и не является поддерживаемым сценарием.

Run сохраняется в Created до начала исполнения. `SaveRunAsync(run, expectedVersion)`
принимает последнюю сохранённую версию; после нескольких доменных изменений она может
отличаться от текущей версии объекта. Снимки входов, сведения о начатом процессе и
существующие метрики не перезаписываются. Добавляются только новые точки и метаданные
жизненного цикла. UPDATE с проверкой версии и транзакция защищают от конкурентной записи.
При конфликте пакет откатывается и возвращается `CatalogException` с кодом `VersionConflict`;
скрытых повторов нет. Терминальные Run не перезаписываются. Подход соответствует
[документации EF Core](https://learn.microsoft.com/en-us/ef/core/saving/concurrency).

## Проверка Git

Git берётся из PATH хоста, а не импортируемого каталога. Используются только фиксированные
команды чтения с отдельным списком аргументов, без shell, с чтением обоих потоков,
лимитом 5 секунд и 64 Ки символов на поток для каждой команды. Переопределения через
GIT-переменные, system/global-конфигурация, fsmonitor и clean/smudge/process-фильтры отключены.
Без фильтров статус может консервативно пометить файл изменённым.

HEAD, origin URL и dirty — best-effort. Из HTTP/SSH URL удаляются credentials, query и
fragment. Нет Git, workspace не является корнем репозитория, отсутствует HEAD или
превышены лимиты — возвращаются неизвестные поля и диагностика. Подмодули не обходятся;
наличие gitlink не позволяет утверждать, что всё дерево чистое. Эти сведения не гарантируют
точную воспроизводимость. Команды не делают fetch/clone, не обращаются к remote и не
запускают определения исследовательских задач.

## Проверки и следующий этап

Команды restore/build/test/format есть в README. Интеграционные тесты проверяют реальные
SQLite-миграции и повторное открытие, скалярные типы снимков, устаревшие/конкурентные записи,
неизменяемость данных, конфигурации, отсутствующие/выходящие наружу пути, цепочки ссылок,
доверие и clean/dirty/non-Git/unborn Git. Проверено на Windows; Unix пока не проверен.

Следующий этап — M3: запуск процесса, отмена/тайм-аут, ограниченное параллельное чтение
stdout/stderr, история Run и восстановление Interrupted. M2 хранит Run, но не исполняет
его и не заявляет проверенную изоляцию процессов, регистрацию артефактов или безопасность
публикаций.
