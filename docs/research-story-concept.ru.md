# ResearchLab — Концепция Research Story

> Статус: направление проектирования, не новое обязательство реализации · 2026-10-24
> Связанные документы: [VISION](../VISION.ru.md), [DOMAIN](../DOMAIN.ru.md), [План реализации](../IMPLEMENTATION_PLAN.md), [Дорожная карта визуализации](visualization-roadmap.ru.md).

## Назначение

**Research Story — интерактивная инженерная публикация, опирающаяся на проверяемые результаты**, которая сочетает техническое повествование, журнал экспериментов и при необходимости демонстрацию проекта. Она помогает читателю разобраться, что создано, почему выбраны конкретные решения, как развивалась реализация и на чём основаны выводы.

**Research Workspace** — рабочая среда автора для импорта проектов, выполнения экспериментов, просмотра логов и изучения результатов. **Research Story** — отобранное и структурированное представление исследования для читателя. Публичная публикация не должна давать доступ к локальным исполнительным функциям автора.

ResearchLab — не просто Markdown-редактор с графиками: ключевая ценность — явная связь выводов с конкретными данными исследования.

## Три концептуальные области

1. **Narrative (повествование):** разделы на усмотрение автора, Markdown, код, формулы, изображения, таблицы и пояснения.
2. **Evidence (подтверждающие материалы):** ссылки на конкретные Run, ряды метрик, графики, артефакты, Git-версии, параметры и окружение запуска, результаты тестов и ограничения.
3. **Publication (публикация):** переносимый неизменяемый экспорт только для чтения с явно выбранными материалами, доступный без локального сервиса автора.

Это разделение ответственности, **а не требование создать три сервиса или три отдельных агрегата**.

## Типы блоков (не иерархия классов для MVP)

| Блок | Назначение | Приоритет |
| --- | --- | --- |
| Markdown / заголовки / текст | Структура, ссылки, списки | MVP |
| Код | Фрагменты с подсветкой синтаксиса | MVP; достаточно Markdown-блоков |
| Формула | Математические обозначения | MVP, если есть безопасный переносимый рендерер |
| Изображение | Иллюстрации и подписи | MVP |
| Run | Данные конкретного запуска и его происхождение | MVP |
| Chart | Сохранённые ряды метрик и сравнения | MVP |
| Artifact | Просмотр или загрузка явно выбранного файла | MVP |
| Comparison | Структурированное сравнение нескольких Run | Позднее; для MVP достаточно сравнения графиков |
| Git history | Коммиты, изменения, эволюция | Позднее; в MVP сохраняются SHA и dirty state |
| Mesh / 3D viewer | Инженерные сетки и геометрия | После MVP |
| Interactive demo | Переключение готовых сценариев; затем контролируемое выполнение | После MVP |
| Custom visualization | Авторский программируемый компонент | В дальнейшем, после проектирования безопасности |

**В MVP не нужно создавать отдельный доменный класс для каждого блока.** Достаточно Markdown и небольшого набора версионированных ссылок/директив на материалы (условный синтаксис: `{{run:run-id}}`, `{{chart:chart-id}}`). Это **пример идеи, а не утверждённый контракт парсера**. Ссылки проверяются при создании и экспорте.

## Гибкие шаблоны исследований

Не требовать одну универсальную структуру. В будущем можно предлагать необязательные шаблоны:

- **Численный алгоритм:** задача → метод → эксперименты → точность/производительность → инженерные решения → ограничения.
- **Backend/инфраструктура:** требования → архитектура → реализация → тесты → наблюдаемость → компромиссы.
- **Симуляция:** модель → гипотеза → методика → результаты → интерпретация → ограничения.

Все разделы необязательные и редактируемые. Читатель должен быстро понять исследовательский вопрос, основные результаты и ограничения.

## Evidence links — ключевая идея

Автор связывает утверждение, абзац, график или раздел с конкретными подтверждающими объектами:
- ID Run и неизменяемый снимок условий его запуска;
- измеренные точки метрик или график, построенный на их основе;
- выбранные артефакты и их контрольные суммы;
- Git SHA, признак незакоммиченных изменений и сохранённое описание окружения;
- результаты тестов/бенчмарков, если они зарегистрированы как данные.

Читатель может открыть параметры, версии и первичные измерения. **Ссылка на данные не доказывает научную истинность вывода.** ResearchLab не сертифицирует утверждения, не заменяет рецензирование и не придумывает результаты бенчмарков.

Ссылки в Story используют **стабильные идентификаторы**, а не «последний Run». Публикация фиксирует или явно сохраняет доступ к именно тем материалам, на которых основана конкретная редакция.

## Редактор и публикация

Предлагаемый сценарий MVP:
1. Создать Story внутри Project.
2. Указать название, краткое описание и Markdown-текст.
3. Выбрать конкретные Run, метрики/графики и Artifacts своего проекта.
4. Просмотреть текст вместе со связанными компонентами.
5. Экспортировать автономный статический HTML и выбранные материалы/данные.
6. Открыть публикацию на другом компьютере без запущенного ResearchLab.

В первой версии достаточно Markdown-поля с предпросмотром и простой вставкой ссылок на данные. **Не создаём Notion-подобный редактор, drag-and-drop-конструктор окон или универсальный плагин-хост в MVP.**

Публичная страница доступна только для чтения. Интерактивные графики могут исследовать **включённые в экспорт измерения**, а предвычисленные демонстрации явно помечаются. Произвольное выполнение кода посетителями не входит в M6.

## Достоверность, безопасность и переносимость

- Не выдавать тестовые фикстуры, иллюстративные графики, предвычисленные симуляции или изображения за реальные экспериментальные измерения.
- Графики основаны на сохранённых метриках; внешние материалы атрибутируются и помечаются.
- Ссылки закреплены за конкретными ID Run/Artifact, а не изменяемыми псевдонимами.
- Publication — неизменяемый снимок; редактирование Story создаёт новый экспорт.
- Обрабатывать Markdown и недоверенный контент безопасно, ограничивать URL-схемы; произвольные скрипты в MVP запрещены.
- Экспортировать только выбранные файлы; не раскрывать локальные абсолютные пути, секреты, приватные настройки и доступ к исполнению.
- Обеспечить просмотр графиков без исходной БД/API через включённые данные, ресурсы или резервные изображения.
- Незакоммиченные изменения и неполные сведения об окружении явно указываются как ограничения воспроизводимости.
- Учитывать доступность интерфейса, подписи, единицы измерения и описание методики, а не использовать графики просто как украшение.

## Соответствие этапам

- **M3:** без Research Story; выполнение и история Run.
- **M4:** реальные метрики и неизменяемые артефакты.
- **M5:** просмотр данных и настройка простых line/scatter-графиков.
- **M6:** Markdown-черновики Story, простые ссылки на данные, предпросмотр и неизменяемый статический экспорт.
- **После MVP:** расширенные шаблоны, сравнения и история, 2D/3D, составные панели, контролируемые демо, пользовательские viewer после разработки модели безопасности.

## Открытые решения

- Синтаксис встроенных ссылок на результаты или структурированное дерево документа.
- Нужны ли впоследствии отдельные сущности Claim/Evidence; **для MVP не нужны**.
- Способ сериализации графиков и включения их данных в статический HTML.
- Переносимый рендеринг формул и предпросмотр.
- Как обеспечить интерактивность без доступа к недоверенным скриптам.

**Критерий пользы:** работодатель открывает экспортированную Story, понимает инженерные решения, видит конкретные запуски, подтверждающие выводы, и изучает результаты без компиляции проекта.
