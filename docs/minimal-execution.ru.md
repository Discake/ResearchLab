# Минимальное локальное исполнение доверенной программы

Управляемая foreground-отмена описана в [контракте отмены](managed-cancellation.ru.md).
Описание исполнения и очистки ниже учитывает это обновление.

Реализован синхронный сценарий Application через настоящий адаптер Execution поверх M3.1a.
Это часть M3, а не весь этап.

```csharp
var inspector = new WorkspaceInspector();
var catalog = new ProjectCatalog(store, inspector);
// Импортировать проект/создать Experiment, показать ReviewTaskAsync, затем вызвать
// ConfirmTaskAsync только после одобрения владельца. Сохранить тот же catalog.
var logFiles = new RunLogFiles(privateLogRoot);
var execution = new RunExecution(store, catalog, inspector, new ProcessRunner(logFiles));
var runId = await execution.StartRunAsync(experimentId, parameters, cancellationToken);
var run = await store.GetRunAsync(runId, cancellationToken);
var logs = new RunLogs(store, logFiles);
var paths = await logs.GetPathsAsync(runId, cancellationToken);
await using var stdout = await logs.OpenReadAsync(runId, RunLogStream.Stdout, cancellationToken);
```

Вызывающий связывает существующие компоненты Application/Infrastructure и
ResearchLab.Execution.ProcessRunner; DI-контейнер, CLI и хост не добавлены.
IProcessRunner принадлежит Application. Execution не зависит от Infrastructure,
не обращается к БД и не меняет доменное состояние. Callback подтверждает реальный старт;
Application сохраняет Running до принятия результата. Если callback завершается ошибкой,
runner останавливает принадлежащий попытке процесс и передаёт ошибку без повторного запуска.

StartRunAsync ждёт завершения и сохранения терминального статуса, затем возвращает RunId.
Это намеренно более простой синхронный сценарий по сравнению с ранним подтверждением
старта из проекта жизненного цикла. Ошибки подготовки/валидации возникают до вставки.
Ошибка старта возвращает ID сохранённого Failed без PID, времени старта и exit code.
Ненулевой код даёт Failed с фактическим exit code; нулевой код и успешное ограниченное
дренирование потоков дают Succeeded. Протокола метрик/артефактов ещё нет; успех не доказывает
научную корректность или наличие ожидаемых измерений.

Снимки используют валидацию/defaults и фабрики Domain. Перед созданием Run выполняется
свежая best-effort инспекция исходников; недоступные сведения Git остаются неизвестными.
Повторно загруженное определение структурно сравнивается с подготовленным. Created
сохраняется до передачи исполнителю; непосредственно перед исполнением доверие повторно
проверяется относительно подготовленного fingerprint. Позднее изменение Experiment не
переписывает Run. Сохранение использует последнюю записанную версию без автоматических
повторов конфликтов или запуска. Ошибки БД передаются вызывающему без заявления о сохранённом исходе.
Обычные исключения исполнителя после подтверждённой очистки дают Failed с общей диагностикой
без выдуманного exit code.
Ошибка подтверждения старта сохраняется как исходная ошибка приложения/БД, даже если
адаптер оборачивает или поглощает её; попытки записать терминальный статус нет. При
неподтверждённой очистке сначала возвращается ProcessCleanupException с владельцем; после
повторной очистки передаётся исходная ошибка подтверждения.
Ошибка чтения/доступа при финальной проверке доверия переводит Created в Failed без запуска.

Runner использует явный executable, буквальные аргументы и проверенный workspace.
Windows использует [native Job launch и ожидание группы](windows-group-lifecycle.ru.md);
non-Windows сохраняет ArgumentList/UseShellExecute=false. На Windows разрешены только .exe: .cmd/.bat могут
включать командный процессор даже при UseShellExecute=false. Контракты импорта/review M2
не менялись; неподдерживаемый файл безопасно отклоняется на этапе исполнения. На Unix
действуют права исполнения и разрешение интерпретатора ОС; исполнение на Unix не проверено.
Доверие по-прежнему покрывает входной файл/конфигурацию, а не транзитивные библиотеки,
интерпретаторы и runtime-файлы. Это доверенный локальный код, не песочница ОС; явно
объявленные executable-интерпретаторы остаются кодом, который владелец должен проверить.

Проверенные скалярные параметры передаются JSON-текстом, совместимым с UTF-8, через
RESEARCHLAB_PARAMETERS_JSON без подстановок в команды. Вместо наследования stdin
используется закрытый перенаправленный ввод. stdout/stderr параллельно дренируются
фиксированными буферами и сохраняются раздельно как сырые байты. Фиксированный общий лимит 1 MiB
останавливает избыточный вывод с Failed. На Windows timeout ограничивает всю Job-группу;
выход корня не выигрывает поздний cancel/deadline при живых потомках. Требуются root exit/code,
нулевой Job accounting и успешный сбор. Очистка использует TerminateJobObject, ограничивая
подтверждение пятью секундами, затем отдельно drains пятью секундами. Non-Windows сохраняет
root/best-effort tree semantics. При неподтверждённой остановке/очистке ProcessCleanupException
сохраняет владельца для явного повтора очистки без терминальной записи. Отменённое чтение
означает ошибку сбора, а не EOF.

CancellationToken в StartRunAsync действует только до первоначальной вставки включительно.
После сохранения Created foreground-сценарий владеет исполнением и обязательной записью
состояний до завершения. Для явной отмены используется PrepareRunAsync с сохранением
RunOperation: ExecuteAsync выполняет попытку, WaitAsync(token) отменяет только ожидание,
RequestCancellation запрашивает остановку. Гонки, повторы и подтверждения описаны в контракте
управляемой отмены. Детали и страницы истории доступны через [RunHistory](run-history.ru.md).
Фоновое исполнение и регистрация артефактов M4 не реализованы. M3.6 добавляет [каталог результатов Run](local-run-completion.ru.md).
Явное восстановление теперь описано в [контракте M3.3](run-recovery.ru.md).

Наследуемое окружение не изолируется. Гонки файловой системы TOCTOU и окно сбоя между
стартом ОС и записью Running остаются согласно проекту жизненного цикла. Windows содержит
обычных CreateProcess-потомков в приватном Job и после root exit; полная матрица crash tests
остаётся M3.7d. Non-Windows не гарантирует очистку потомков после root exit. Job containment
не является файловой/security sandbox.

Тесты используют отдельную синтетическую программу из tests, а не продуктовый CLI или
экспериментальные доказательства. Проверяются реальный SQLite и порядок состояний,
ошибка старта, отсутствие доверия, ошибки параметров, подмена executable, буквальные
аргументы, передача параметров, оба потока вывода, timeout, лимит вывода и очистка при
ошибке callback.
Регрессионные тесты также покрывают исключения исполнителя до/после старта, реальные ошибки
записи SQLite при старте/завершении, медленное подтверждение, ошибку чтения при финальной
проверке доверия, неполный результат и очистку живого дерева с потомком, наследующим оба потока.

## Ограниченное сохранение логов M3

Хост задаёт приватный корень RunLogFiles вне импортированного workspace; путь не берётся
из конфигурации задачи или stdout. IProcessRunner получает сохранённый RunId от Application.
При передаче исполнителю создаётся каталог `<RunId:N>` с stdout.log и stderr.log до старта ОС.
Ошибки доверия до передачи не создают логи. Ошибка выделения хранилища предотвращает старт
и сохраняется как Failed без приватных путей. Повторное использование каталога отклоняется;
существующие файлы не перезаписываются. Миграция БД не нужна: пути вычисляются по RunId.

Общий лимит сохранения — 1 MiB на Run; распределение между потоками зависит от порядка
чтения. Буферы по 8192 байта не накапливают весь вывод. Превышение лимита по-прежнему
останавливает процесс с Failed; сохраняется ограниченный префикс каждого потока.
Ненулевой exit, timeout и ошибка callback не удаляют записанные данные. При сбое диска
сохранение частичное, успешный результат не заявляется. Аварийное завершение хоста может
потерять последние буферизованные байты; fsync и гарантия сохранности при сбое питания не добавлены.

RunLogs проверяет наличие Run в store; GetPathsAsync возвращает относительные пути,
OpenReadAsync принимает только RunId и enum Stdout/Stderr. Произвольный путь/имя файла
не принимаются. Старые Run без каталога возвращают null; чтение отсутствующего файла
выдаёт ошибку файловой системы. Корень, его предки, каталог Run и файлы проверяются
на reparse point/symlink/junction при создании и чтении. Конкурентная подмена между
проверкой и открытием остаётся TOCTOU-ограничением доверенного локального хранилища:
это не защита от враждебного процесса с правами записи в корень/его предков. Хост должен
ограничить эти права. M3.6 передаёт RESEARCHLAB_OUTPUT_DIR для
[результатов Run](local-run-completion.ru.md); это не Artifact Storage M4.
