# Протокол метрик — M4.1

`MetricProtocol.Parse(ReadOnlySpan<byte>)` в Application разбирает одну полную строку
stdout без зависимостей от Run, хранилища, исполнителя и файловой системы. Результат:
`MetricParseResult.Metric`, `OrdinaryLine` либо `Error(Code)`. При ошибке метрика не
создаётся; даже корректный DTO ещё не является сохранённым `MetricPoint`.

```text
@researchlab/v1 {"type":"metric","name":"residual","value":0.0024,"step":15,"unit":"1"}
```

Маркер регистрозависимый, с нулевого байта, затем один ASCII-пробел и JSON-объект.
Дополнительные JSON-пробелы разрешены. Отсутствующий разделитель или табуляция вместо
него — ошибка envelope. Маркер с непробельным суффиксом (включая v10), с отступом
или внутри текста — обычный лог. Неизвестные версии протокола пока остаются логами.
Допустимы отсутствие окончания строки, один LF или CRLF; внутренние сырые CR/LF
отклоняются. BOM перед маркером не поддерживается. Вызывающий код выделяет строки
и сохраняет исходные байты **при любом** результате, включая логи и ошибки.
Парсер не читает поток и не удаляет логи. Обычные логи не декодируются: некорректный
UTF-8 без маркера остаётся обычным логом.

События используют строгий UTF-8 без замены ошибочных последовательностей.
Некорректный UTF-8 возвращает `InvalidUtf8`; ошибочный JSON (включая неверные
суррогатные escape-последовательности), комментарии, завершающие запятые, несколько
JSON-значений и превышение глубины — `InvalidJson`. Ключи регистрозависимы.
Повторные декодированные ключи, включая escape-эквиваленты, дают `DuplicateField`.
Обязательный `type` должен быть строкой; всё кроме `metric`, явно включая `artifact`,
даёт `UnsupportedEventType`. Содержимое artifact не интерпретируется. Для метрики
неизвестные поля дают `UnknownField`, отсутствие name/value — `MissingField`.

| Поле | Контракт |
| --- | --- |
| `type` | Обязательная строка, строго `metric`. |
| `name` | Обязательная непустая и не полностью пробельная строка без управляющих Unicode-символов. Сохраняется дословно. |
| `value` | Обязательное JSON-число, представимое конечным double; переполнение отклоняется. Действуют округление и underflow double. |
| `step` | Необязательный целочисленный токен Int64 со знаком, отрицательные допустимы. Дроби, экспоненциальная запись и переполнение отклоняются. |
| `unit` | Необязательная непустая и не полностью пробельная строка без управляющих Unicode-символов. Сохраняется дословно. |

Явный null недопустим для всех полей. Неверный JSON-тип даёт `InvalidFieldType`,
неверный текст — `InvalidName`/`InvalidUnit`, неконечный double — `InvalidValue`,
неверный целочисленный токен — `InvalidStep`. Неизвестные научные единицы принимаются:
нет whitelist, научной грамматики, нормализации и преобразований. Проверяется только
синтаксис текста; Domain по-прежнему проверяет точное совпадение единиц внутри серии.
Непарные суррогатные escape-последовательности отклоняются без скрытой замены.

## Ограничения ресурсов

- Максимум **8192 байта**, включая маркер, разделитель, JSON и завершающие пробелы,
  исключая один финальный LF или CRLF. Проверяется до декодирования и выделения JSON.
  Достаточно для небольших числовых событий с описательными Unicode-именами;
  память и работа одного вызова ограничены значительно ниже общего лимита
  stdout/stderr **1 MiB на Run**.
- Максимальная глубина JSON — **4**; корректной метрике достаточно глубины 1.
- Выделения памяти ограничены размером события: копия payload, JSON-документ,
  декодированные ключи и строки. Накопления между вызовами нет; логи не копируются.
- Одна диагностика в виде enum-кода на строку, без пользовательского содержимого,
  путей, текста исключений JSON и неограниченных фрагментов. Возвращается первая
  выявленная ошибка, а не полный список.

Некорректные данные возвращают ошибку без исключения наружу. Исчерпание ресурсов
среды не является восстанавливаемой ошибкой протокола. Вызывающий код обязан выделять
строки с ограниченной буферизацией: парсер не ограничивает память до своего вызова.

## Отложенная политика

Этот этап не принимает метрики в Run, не назначает время/sequence, не сохраняет данные
и не меняет Run. Он не решает, должна ли диагностика завершать Run ошибкой.
Число событий, общее число метрик, хранение/частота диагностики и поведение при
обрезании stdout требуют политики интеграции. Лимит Run 1 MiB не меняется и не
заменяет ограничение буфера строки. Научная грамматика/реестры единиц и расширенная
совместимость остаются открытыми; изменения должны сохранять доказательства без
скрытых преобразований. Stdout — данные, а не инструкции ResearchLab.
Артефакты, SDK и UI не входят в M4.1.
